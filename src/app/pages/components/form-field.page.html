The field owns the id Its <label for> has to point at the control, and only one of them can win. Pass id to the field, never to the control. An error is an invalid state The message sets aria-invalid on the control and joins its aria-describedby. The red border and the announcement can never disagree. The atom stays dumb <ds-input> does not import the field. It asks whether one is there, and works on its own when it is not.

Errors arrive when the user has had a go A field that turns red while it is being typed into is a field that shouts at someone for not having finished. Paint's examples show the message once the control is touched, or once Save has been pressed — and then keep it live, because by then the user is fixing it. Don't Wrap a checkbox or a switch. Their label belongs beside the control, which is where the atom puts it — and a <label for> above a set of them would name the first and leave the rest anonymous. Do Use the atom's own label for a single checkbox, and <ds-radio-group> or <ds-checkbox-group> for a set — a <fieldset> with a <legend> is the only markup that attaches a question to its answers.
